# 夜泊 Night Harbor V3

給白天被事情塞滿、晚上捨不得睡的大學生，一個能實際操作的手機網頁專題原型。包含帶引用的個人化 RAG、真正由 AI 決定的每日作息目標，以及個人 emoji 寵物、金幣養成、每日回報與每週 recap。

## 開始使用

需要換網路後仍使用同一網址時，使用 `start-fixed-url.cmd` 或 `npm.cmd run public`，見 [固定網址使用說明](FIXED-URL.md)。固定網域由 ngrok 提供，電腦仍需開機。

首次開啟會顯示登入／註冊畫面。帳號與個人資料使用 SQLite 保存，詳細操作、同步方式與資料庫備份見 [帳號使用說明](ACCOUNTS.md)。

要在 iPhone 安裝使用，請先看 [iPhone 安裝說明](IPHONE.md)。雙擊 `start-iphone.cmd` 或執行 `npm.cmd run iphone`，依啟動視窗顯示的區網網址，在 Safari 加入主畫面。

開啟首頁會先進入寵物房間；尚未領養時顯示夥伴選擇與命名。電腦與手機皆使用左側直向工具列，依序可切換寵物首頁、生活紀錄、睡眠回報、作息路徑、睡眠知識、睡前收尾與偏好設定；圖示附有短標籤，選中的頁面會標示亮色。點左上月亮圖示可回到寵物首頁。

左側「好友」提供帳號搜尋與邀請、最多五人的小組共養、狀態分享與晚安提醒、早安打卡牆、好友／小組排行榜，以及進步與連續達標獎勵。操作與完整結算規則見 [好友與共養說明](SOCIAL.md)。

### 1. 確認執行環境

安裝 Node.js 22.13.0 或更新版本，重新開啟終端機後確認版本：

```powershell
node --version
npm --version
```

`node --version` 應顯示 `v22` 或更新版本。本專案無第三方套件，不需要執行 `npm install`，也沒有額外的前端建置步驟。

### 2. 設定 Gemini API 金鑰

先在終端機切換到含有 `package.json` 的專案根目錄。Windows PowerShell 範例（專案放在其他位置時，請替換路徑）：

```powershell
cd "$HOME\Desktop\人工智慧實務專題"
```

若電腦已有 `GEMINI_API_KEY` 環境變數，可直接使用；否則在專案根目錄複製設定範本：

```powershell
Copy-Item .env.example .env
notepad .env
```

若 `.env` 已存在，直接編輯即可，不要重新複製覆蓋。macOS／Linux 可在專案根目錄執行 `cp .env.example .env`，再用文字編輯器開啟。

將 `.env` 填成以下格式，把佔位文字換成自己的金鑰：

```dotenv
GEMINI_API_KEY=在此填入自己的金鑰
GEMINI_MODEL=gemini-3.5-flash-lite
PORT=3000
HOST=127.0.0.1
```

檔名必須是 `.env`，不是 `.env.txt`，並與 `server.mjs` 放在同一層。不要把金鑰貼到網頁、聊天、Git 或投影片。預設模型為 `gemini-3.5-flash-lite`，可用 `GEMINI_MODEL` 修改；API 使用量、費用、額度依自己的 Google 專案而定。

未設定金鑰仍可啟動網頁、操作本機紀錄、睡前小動作與寵物介面，但需要 Gemini 的知識建議、作息目標及 AI 回報無法正常產生。已設定金鑰也不代表每次請求一定可用；介面會顯示服務錯誤，不會偷偷改成預寫回覆。

### 3. 啟動專案

**方式 A：Windows 雙擊啟動**

在專案資料夾雙擊 `start.cmd`，保持開啟的命令視窗運作。這個檔案會自動切換到專案目錄並執行 `node server.mjs`。

**方式 B：終端機啟動（Windows／macOS／Linux）**

在專案根目錄執行：

```sh
npm start
```

也可以直接執行相同的伺服器入口：

```sh
node server.mjs
```

看到以下訊息代表伺服器已啟動；第二行會依是否設定金鑰而不同：

```text
Night Harbor / 夜泊: http://127.0.0.1:3000
Gemini: configured
```

接著自行在瀏覽器開啟 <http://127.0.0.1:3000>。請透過這個網址操作，不要直接雙擊 `public/index.html`，因為網頁功能需要同時連接後端 API。

### 4. 確認啟動與停止方式

開啟 <http://127.0.0.1:3000/api/health> 可查看啟動狀態。`configured: true` 表示伺服器有讀到非空白金鑰，**不代表已驗證金鑰有效或 Gemini 連線成功**；實際連線需透過網頁中的 AI 功能確認。這個端點不會回傳金鑰內容。

使用期間需保持啟動視窗開啟。要停止服務，在該視窗按 `Ctrl+C`；下次使用時重新執行 `start.cmd` 或 `npm start` 即可。修改 `.env` 後也要停止並重新啟動，設定才會重新載入。

### 開發模式

修改程式時可在專案根目錄執行：

```sh
npm run dev
```

此指令使用 Node.js 的 `--watch` 模式，伺服器程式與其匯入模組變更時會自動重新啟動。修改 `public/` 內的 HTML、CSS、JavaScript 後，重新整理瀏覽器即可查看；這個模式不會自動重新整理網頁。

### 常見啟動問題

| 狀況 | 處理方式 |
| --- | --- |
| 找不到 `node` 或 `npm` 指令 | 確認已安裝 Node.js 22.13.0 或更新版本，重新開啟終端機，再執行版本檢查。 |
| PowerShell 顯示無法執行 `npm.ps1` | 改用 `npm.cmd start`，或直接執行 `node server.mjs`。開發模式可改用 `npm.cmd run dev`。 |
| 顯示找不到 `package.json` 或 `server.mjs` | 確認終端機目前位於專案根目錄，再執行啟動指令。 |
| 顯示 `Port 3000 is in use` 或 `EADDRINUSE` | 在 `.env` 將 `PORT` 改為 `3001` 後重新啟動，並開啟 `http://127.0.0.1:3001`；健康檢查網址也要改用相同連接埠。 |
| 顯示 `Gemini: not configured` 或 `configured: false` | 確認 `.env` 的位置、檔名與 `GEMINI_API_KEY` 是否填妥，儲存後重新啟動。 |
| 網頁可開啟，但 AI 功能顯示錯誤 | 依介面訊息檢查金鑰、模型設定、網路及 API 額度；`configured: true` 只表示有設定金鑰。 |
| 瀏覽器無法連線 | 確認啟動視窗仍在執行且沒有錯誤，並使用啟動日誌實際顯示的網址與連接埠。 |

`start.cmd` 的開場提示固定顯示連接埠 `3000`；若修改了 `PORT`，請以伺服器輸出的 `Night Harbor / 夜泊: ...` 網址為準。

預設僅綁定本機（`HOST=127.0.0.1`）。這是本機展示原型，已加入帳號隔離與 SQLite 保存；公開部署仍需另外安排 HTTPS 與維運設定。

## 個人寵物與每日／每週回報

### 個人寵物與金幣

- 從六種常見 emoji 選擇小貓、小狗、小兔、小狐狸、小熊貓或小貓頭鷹，取名並保存至帳號。
- 使用者設定最終希望上床時間，AI 分析每天的紀錄並產生今晚目標。只保存當晚目標與設定時間；已到目標時間的約定不事後更改。
- 次日回報「上床準備睡覺時間」。若不晚於事先目標十五分鐘，獲得二十枚金幣；提早上床也符合約定。同一夜晚只有一筆獎勵，修改、刪除再重填不重複發放。
- 獎勵依可自行控制的上床時間，與真正入睡時間分開；有難入睡或夜醒也不扣幣、不懲罰寵物。
- 餵食花五枚金幣，六種家具可購買、擺放及收起。交易真的扣除餘額，不足時不能購買，已買的家具不重複收費。
- 進步與連續達標獎勵由後端結算，小組有獨立金幣與共養寵物。這是沒有金錢價值的虛擬貨幣；未接手機螢幕時間或穿戴裝置，自行回報不等於自動驗證。

### 每日回報

早晨填寫上床、估計入睡、起床、睡眠自評 1–5 分，以及是否難入睡或夜醒。最多追蹤五項生活因素：咖啡因、運動、睡前螢幕、睡前情緒、午睡。

回報會呈現是否依約上床、睡眠感受、今晚的暫定就寢與收心時間，並列出有來源支持的可觀察線索。按「產生今日 AI 回報」會真的呼叫 Gemini 與 RAG，整理今天可嘗試的做法。

咖啡、運動、午睡使用起床前一天的資料；螢幕和情緒使用前一晚的資料。空白是未知，不當成零，也不把同時出現當成造成失眠的原因。自述困擾不等於診斷失眠症。

### 每週 recap

比較最近七天與前七天，顯示睡眠自評趨勢、平均上床時間、按時上床比例、疲勞與自述困擾晚數。時間跨午夜計算；百分比的變化顯示為百分點。變化可為改善或退步，不預設一定進步。

每項比較要求兩段期間各至少三筆該項資料，否則顯示資料不足；圖表的缺填處保留空白，不補零。每週 AI recap 使用同一份程式計算的事實，再結合檢索來源生成回顧與下週方向。

### 當場展示，不用等兩週

「更多／偏好設定 → 專題展示 → 進入示範模式」。會載入清楚標示的虛構十四天資料與示範寵物，能實際餵食、買家具、看週報及呼叫 AI。示範操作不寫入原本資料；按「回到我的資料」或重新整理即離開。匯出的 JSON 也會標記是否為示範。

## AI 功能與收心提醒

### 收心提醒與睡前小動作

- 「偏好設定」啟用提醒後，前端每 30 秒檢查作息路徑中的收心時間、頁面是否可見、最近五分鐘是否有操作。
- 時間到且仍在使用頁面時，顯示收心提醒，可直接選擇睡前小動作或延後十分鐘；設定頁有提醒預覽按鈕，方便展示。
- 首頁可直接選擇放遠手機、調暗燈光或留下明天的一件小事，完成後顯示結束頁。小動作與選填紙條會保存至帳號，不呼叫 AI。
- 網頁無法讀取其他 App 使用時間，也不能保證關閉或鎖定後繼續提醒。可下載今晚的行事曆提醒，由裝置處理通知。

### 1. 個人化睡眠知識庫（RAG）

- `knowledge.mjs` 包含九則經整理、有原始連結與查閱日期的知識摘要：咖啡因、作息與光線、運動、壓力、成人睡眠時數、營養品證據限制。
- `retrieve()` 先以關鍵詞、標籤與中文雙字比對取得相關片段。這是檢索增強生成，使用的是輕量詞彙檢索，**沒有假裝已建置向量資料庫或 embedding**。
- `advice.mjs` 將取回片段、使用者問題及最近七天紀錄交給 Gemini，以結構化 JSON 產生建議。
- 建議中的來源 ID 必須存在於本次檢索結果，後端驗證後才顯示。這能排除捏造引用 ID，但不代表已自動證明每句話都被來源支持；展示前仍應人工檢閱內容。
- 資料不足時說明限制。空白紀錄是「未知」，不當成「沒喝咖啡」。日期區分前一晚睡眠與當天咖啡、運動，避免把先後關係說反。
- 不提供營養品或藥物品項、劑量與服用時程；現有來源不足以推算某個重訓者的最佳睡眠需求。

若後續要擴大文獻量，可替換 `retrieve()` 為向量或混合檢索，保持來源 ID、網址及引用驗證介面；不必重寫前端。

### 2. 真正由 AI 決定的每日作息目標

- 「最終希望幾點上床」是使用者設定的長期方向；「今晚 AI 建議上床」是 Gemini 依個人資料做出的當日決策，兩者分開顯示。
- 每次新增、修改或刪除生活紀錄，會自動重新請求 AI 分析。換到新的夜晚且網頁開啟時，也會產生新一晚目標。設定、資料及夜晚日期相同時，沿用帳號已保存的分析，重新整理不會任意變動目標。
- 分析資料包括最近十四天的上床、實際入睡、起床、睡眠自評、疲勞、難入睡或夜醒、情緒、螢幕、咖啡因、運動、午睡，以及已保存目標的依約情形。缺填為未知；白天行為與下一個起床日的睡眠配對。
- 參考起點優先使用最近十四天內、最多七筆上床時間中位數，至少三筆；不足時相容舊版入睡資料或自填通常上床時間。這只是觀察基準，不直接等於今晚建議。
- AI 可選擇維持或小幅提早，並解釋個人化理由和一項行動。為避免一次跳太多，後端只接受參考起點之前最多三十分鐘、且不跨越最終目標的建議；已達標則維持原作息。這是產品界限，不是醫療驗證的最佳調整幅度。
- 已移除對使用者預排固定十四晚的功能；不要求每晚提早十五分鐘。未使用的舊版未來預排目標會清除，過去已保存的約定和金幣保留。
- 新目標在就寢前保存，當晚獎勵、首頁、回報與提醒都使用同一個時間。時間已到就鎖定，避免事後改標準。上床和真正入睡分開，入睡困擾不扣獎勵。
- AI 失敗、輸出格式錯誤、捏造來源或超出調整範圍時，明確顯示錯誤。若有當晚已保存目標就沿用並標示尚未更新；沒有則等待重試，不以規則排程假稱 AI 目標。
- 就寢時間由 AI 決定；開始收心和調暗燈光分別由此時間往前推三十分鐘、十五分鐘。只下載今晚三個行事曆提醒，隔天需重新產生。
- 來源提供一般生活知識，不代表文獻證明某個人應該在精確時間睡覺。這不是疾病診斷、失眠療程或最佳生理時鐘預測。

## 建議展示順序

1. 「生活紀錄」填入三天自己的或已取得同意的測試資料；如使用虛構資料，報告時明確標示。
2. 「作息路徑」設定通常就寢、希望就寢與起床時間，展示最終目標與今晚 AI 目標的差異，以及分析理由與反向推算提醒。
3. 「睡眠知識」提問咖啡因或運動，展示個人紀錄、AI 回覆與可點閱來源。
4. 「偏好設定」按「體驗一次關心提醒」，再直接選擇睡前小動作。
5. 選擇一個收尾動作，展示結束頁。

## 檔案與架構

```text
瀏覽器：登入介面、前景提醒、帳號資料與離線暫存
  → Node.js HTTP API
      → ai.mjs：共用錯誤型別
      → knowledge.mjs + advice.mjs：檢索 → 生成 → 引用 ID 驗證
      → planner.mjs：個人紀錄 + 一般睡眠知識 → Gemini 決策 → 時間範圍驗證
      → domain.mjs：紀錄檢查、跨午夜計算及參考起點
      → reports.mjs：使用已保存的當晚目標產生回報
```

`public/` 是可直接修改的 HTML、CSS、JavaScript，沒有框架建置步驟。`server.mjs` 提供同源靜態網頁與 API。選擇 Node.js 是為了讓目前空白資料夾能用最少依賴直接展示，不是要求專題後續一定沿用這個技術。

API：

| 路徑 | 用途 |
| --- | --- |
| GET `/api/health` | 檢查設定是否存在，不回傳金鑰 |
| GET `/api/knowledge` | 取得知識摘要與來源 |
| POST `/api/records/validate` | 檢查生活紀錄格式，不保存 |
| POST `/api/advice` | 根據來源與紀錄產生建議 |
| POST `/api/plan` | 呼叫 Gemini 分析紀錄、決定今晚目標；已到期的約定只讀取 |
| POST `/api/reports` | 計算每日／每週回報 |
| POST `/api/reports/advice` | 核對回報事實後，呼叫 RAG 與真實 AI |

## 資料處理

帳號與個人資料保存於 data/night-harbor.sqlite；密碼使用加鹽 scrypt 雜湊，登入狀態使用 HttpOnly Cookie。生活、收尾、寵物、金幣、目標與分析快取依帳號隔離，裝置暫存尚未同步的變更，並可匯出或清除。睡前小動作與紙條不傳送至 AI。API 不記錄訊息內容或金鑰。

知識查詢與回報分析會傳送至 Google Gemini；儲存目標、每日紀錄及開啟新一晚頁面時，也會將近期資料傳送以產生當晚作息建議；請求設定 `store: false`，但不代表供應商完全不處理或保留任何資料，仍應查閱 [Gemini API 條款](https://ai.google.dev/gemini-api/terms)。使用免費服務時尤其要先確認其資料使用政策。

此原型提供一般健康資訊，不能判定疾病或保證入睡時間。公開提供健康服務前，仍需睡眠專業人員審閱知識與規劃策略。
